1. Final System Architecture
TARANG uses three application layers: React for the user interface, Spring Boot as the authentication/identity owner, and
FastAPI as the application + processing owner. Nginx provides the single public entry point.

Implementation note: TVG is not a generic image multiplication step. Use the sonar/device calibration profile and correct
units. A dB loss term must not be blindly multiplied into intensity as though it were a linear gain.
Missing IMU metadata should trigger a graceful fallback. The pipeline can retain the frame, record the missing-data quality
flag, and skip or downgrade motion-dependent corrections rather than failing the entire survey.

8. Important Schema Constraints and Indexes
 Area
Final v6.2 behavior
Identity
users.email UNIQUE; roles.name UNIQUE; refresh_tokens.token_hash UNIQUE.
Frame uniqueness
UNIQUE(survey_id, frame_number).
Progress
Job/stage progress constrained to 0–100; attempt/retry counters constrained to valid non-negative ranges.
Quality
Frame, preprocessing and dataset-sample quality scores are NULL-safe and constrained to 0–100.
AI metrics
Detection/model evaluation evidence and metrics are constrained to 0–1 where applicable.
XAI / physics
One xai_evidence and one physics_validation record per detection via UNIQUE detection_id.
Authoritative geotag
Partial unique index allows at most one authoritative geotag per detection.
Review claiming
Partial unique index allows at most one claimed assignment per detection.
PostGIS
GIST indexes on frame, geotag and target location columns.
Materialized view
mv_survey_stats has a unique operator_id index, allowing CONCURRENT refresh.

9. Schema-to-Code Rules
 Alembic is the only migration mechanism in backend-app. Do not create a second migrations directory.
 SQLAlchemy models mirror the database, while Pydantic schemas define API contracts. Do not confuse the two.
 Keep large sonar binaries outside PostgreSQL; database columns store metadata, checksums and artifact/storage URIs.
 When latitude/longitude are authoritative, service code must construct and maintain the corresponding PostGIS location
point.
 Validate cross-table consistency in service logic: detection.survey_id must match frame.survey_id; similar checks apply
to preprocessing_runs and dataset_samples.
 Use repository classes for persistence and services for business rules. Routers/controllers should stay thin.
 Use background workers for heavy SSS processing, inference, XAI and report generation.

11. Required Development Environment
 Git + GitHub/GitLab repository.
 Node.js + npm for frontend development.
 JDK 17+ and Maven for Spring Boot.
 Python 3.11+ (or the version fixed by requirements.txt) for FastAPI/Celery.
 Docker Desktop or Docker Engine + Compose.
 PostgreSQL 14+ with PostGIS 3.2+ (Docker is preferred for consistent development).
 Redis.
 GPU is useful for AI training/inference but is not required for the basic web platform. CPU fallback can support
development and demo-scale processing.
12. Security Architecture
 Spring Boot issues asymmetric JWTs; FastAPI verifies the public key. Use key IDs (kid) to support rotation.
 Refresh tokens are stored hashed, never as plaintext.
 Restrict CORS and preferably expose the application through the Nginx same-origin gateway.
 Rate-limit login, registration, password reset and large upload endpoints.
 Validate upload extension, MIME/content signature, size and expected structure before processing.
 Never expose raw filesystem/storage paths through public APIs; use authorized download endpoints or signed URLs.
 Protect sensitive marine coordinates through role/organization authorization; public map views must use a deliberately
safe representation.
 Use correlation IDs and audit_logs for security-sensitive actions.

13. Testing Strategy
 Level
What to test
Frontend
Component tests, feature behavior, route guards and end-to-end flows.
Spring Boot
Auth, password hashing, JWT, refresh tokens, RBAC, organization/user operations.
FastAPI
API contracts, authorization, validation, repositories and services.
Pipeline
Each preprocessing stage independently plus complete pipeline integration.
Image regression
Golden SSS frames: ensure preprocessing changes do not unexpectedly destroy shadows/targets.
Physics
Synthetic known-geometry tests for slant range, shadow consistency and coordinate calculations.
AI
Precision/recall/mAP/IoU/F1; evaluate by device, environment and survey rather than only a single aggregate score.
Data leakage
Split by survey/source where appropriate so nearly identical frames do not leak across train/test.
Integration
React ↔ Nginx ↔ Spring/FastAPI ↔ PostgreSQL/Redis ↔ worker flows.
